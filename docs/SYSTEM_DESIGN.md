# RogueLike Architecture Ledger

## Dependencies & Core Systems

- **Map Generators:** Procedural generation MUST NEVER reside in `DungeonGrid`. Complex mapping logic must be extracted into static or standalone builder classes (e.g., `BspDungeonGenerator`) that operate on a pure `DungeonGrid`.
- **DungeonGrid:** Pure C# data structure. Maps grid indices to Walkability and tracks out-of-bounds. Default constructor yields a blank featureless floor.
- **ActorRegistry/IActor:** The core dynamic actor registry (Godot-free, `Code/Domain/Actors/`). `GridMover` coordinates with `ActorRegistry` to ensure no two `IActor` instances overlap. The Godot `Node2D` lookup that used to share this class is now the view-side `NodeRegistry` (`Code/View/Entities/`), used only for stairs detection.
- **Actor (pure aggregate, `Code/Domain/Actors/Actor.cs`):** Godot-free base aggregate that **owns** the immutable `Health` VO and the combat verbs that mutate it (`ReceiveDamage(Damage)`/`Heal(int)`/`IncreaseMaxHp(int)`/`ResetHealth(int)`), plus the real `Attack(ICombatant defender)` (deals `Damage`, logs, fires the `OnKilled(victim)` kill-reaction virtual on death). Raises domain events the View renders: `OnHealthChanged(current,max)` + `OnDied`. Concrete subclasses: `Player` (owns its `Loadout`, so `AttackDamage = baseAttack + Loadout.DamageBonus`; overrides `OnKilled`) and `Enemy` (fixed attack + name). Replaces the old `ICombatant.TryAttack` default-interface-method (deleted) and the combat/health rules that used to live on the Godot `ActorController`.
- **Combat & Health:** Pure C# logic. `ICombatant` extends `IActor` and is now the **polymorphic combat contract** the registry/AI reach an actor through (as attacker/defender): `Health`, `AttackDamage`, `ReceiveDamage`, `Heal`, `Die`, and `Attack(ICombatant)`. The behavior lives on `Actor`; the Godot controllers implement `ICombatant` by **delegating to their composed `Actor`**. Callers invoke `attacker.Attack(defender)` (no interface-cast, no DIM). The old static `CombatSystem` service was removed earlier (rich-domain migration).
- **GridMover:** Pure C# movement logic. Supports 8-directional movement. Validates each step via `DungeonGrid.CanStep` (the shared terrain rule), then adds its own occupancy check via `ActorRegistry`.
- **DungeonGrid traversability:** The terrain rule lives on `DungeonGrid` as `CanStep(GridPos, Direction)` = walkable target (built on `IsWalkable`). Diagonals may round wall corners freely (no corner-cut restriction). It is a query over grid topology, so the grid owns it. Reused by both `GridMover` (actual moves) and pathfinding (planned paths), so plans never include steps the mover would reject. Occupancy is **not** part of `CanStep` — that's the mover's concern (the grid knows walls, not actors).
- **Where spatial logic lives (decided principle):** single-impl topology queries that read the grid's own cells fold **onto** `DungeonGrid` (line-of-sight, pathfinding) — the grid owns the walls, so the query lives with the data. Pluggable/swappable algorithms stay **separate injected interfaces** (FOV keeps `IFovAlgorithm`, selected in `Main`). This is the line that keeps the grid cohesive rather than a dumping ground.
- **FOV Array:** Pure C# data structures isolating visibility calculations.
    - `FovMap`: Pure struct tracking `VisibilityState` of every cell.
    - `IFovAlgorithm`: Interface for algorithms (`Raycaster`) that mutate the `FovMap`.
- **EnemyAIBase:** Abstract template-method base for enemy AIs (`Code/Domain/Actors/`). Owns the shared turn skeleton (`TakeTurn()`: act on a visible player → else pursue last-known → forget on arrival/lost-path), the `_lastKnownPlayerPos` memory, the `StepTowards(GridPos)` pure-move helper, and `GridPosition`. Subclasses override only `ActOnVisible(player)`. `EnemyAI` (melee) and `ArcherAI` (ranged) derive from it; this base is the natural seam that folds into the future `Enemy : Actor` aggregate.
  - **Per-enemy sight (own line-of-sight, NOT the player's FOV):** `CanSee(player)` = `DungeonGrid.HasClearLine(self, player)` (walls block) **AND** `GridPos.ChebyshevTo(player) <= _sightRange`. The AI is **fully Godot-free and FOV-free** — it no longer takes a `FovMap`; `TakeTurn()` has no params. `_sightRange` is a ctor arg (`EnemyController`/`ArcherController` expose it as `[Export] SightRange`, default 7, passed to the AI ctor — same pattern as archer `Range`). Sight (7) > archer shoot range (5), so an archer sees the player before it can fire. The player-origin `FovMap` (radius 6) is now **rendering-only** (fog of war, minimap, enemy sprite show/hide in the controllers' `SyncPosition`) — it no longer feeds AI decisions.
- **EnemyAI:** Pure C# decision tree (extends `EnemyAIBase`). `ActOnVisible` = path toward the player and attack on contact. Used by melee Goblins. **Last-known-position memory** (in the base): when the enemy sees the player (own LOS + sight range) it records the player's tile; when the player breaks line-of-sight the AI keeps pursuing that remembered tile (via `grid.FindPath`), and clears the memory on arrival (or if the path is lost) → idle. So kiting/breaking LOS works (the enemy gives up at the last-seen spot) without omniscient chase. Movement math reads the canonical `GridMover.GridPosition` (not the view-synced `_owner` position) so multi-turn pursuit is correct independent of when the controller syncs.
- **ArcherAI:** Pure C# decision tree for ranged enemies (extends `EnemyAIBase`). `ActOnVisible` = shoot if in LOS + shoot range (`DungeonGrid.HasClearLine` + `GridPos.ManhattanTo`, default range 5), else close the distance via `StepTowards`. Inherits per-enemy sight + the **last-known-position memory** from the base — pursuit only drives *movement*; the archer **never blind-fires**, it shoots solely a currently-visible player.
- **Line-of-sight:** A query on `DungeonGrid` (`HasClearLine(GridPos, GridPos)`) — the grid owns the walls, so the LOS query lives with that data. Traces with Bresenham over the grid's own cells; endpoints excluded from the wall check.
- **IEnemy (`Code/Domain/Actors/`):** `IEnemy : ICombatant { int XpReward }` — the **enemy seam**. Hostile combatants that grant XP when killed implement it; the **Player implements `ICombatant` but NOT `IEnemy`**, so it no longer carries a meaningless reward. `XpReward` was removed from `ICombatant`. The kill hook narrows on the **`Player` aggregate**: `Player.OnKilled(ICombatant victim)` does `if (victim is IEnemy e) Experience.AddXP(e.XpReward)` (✅ Phase 3 batch 2) — combat still doesn't know who the attacker is, and grants XP only for enemies.
- **EnemyControllerBase (`Code/View/Enemies/`):** Abstract Godot view base for enemies (`: ActorController, IEnemy`). Houses the enemy-only `[Export]`s (`XpReward`, `SightRange`), the `EnemyAIBase _ai` + `GridPosition`/`IsPlayer`/`AttackDamage`, and the shared `Initialize`/`TakeTurn`/`SyncPosition` skeleton. Subclasses override only `CreateAi(...)` (returns the concrete `EnemyAIBase`). `EnemyController` (→ `EnemyAI`) and `ArcherController` (adds `[Export] Range` → `ArcherAI`) shrink to that one factory. Mirrors the domain-side `EnemyAIBase` template.
- **EnemyController / ArcherController:** Godot `Node2D`s extending `EnemyControllerBase` (which extends `ActorController`). **PlayerController** extends `ActorController` directly (it is not an enemy). They delegate logic to `GridMover`/`EnemyAI`/`ArcherAI` and only handle visual sync + input.
- **ActorController:** Abstract Godot base View for all grid actors (Player + enemies). Holds a pure domain `Actor` (created by the subclass) and **forwards** the `ICombatant` contract to it (`Health`/`AttackDamage`/`ReceiveDamage`/`Heal`/`IncreaseMaxHp`/`Attack` all delegate). It renders the actor's domain events — `OnHealthChanged`→health bar, `OnDied`→`Die()` (SFX + `QueueFree` + unregister) — and plays the hit SFX in `ReceiveDamage`. Keeps the `[Export]`s (`BaseHealth`, `BaseAttackDamage`, `HealthBar`) as the seed stats fed to the actor. **No combat rules live here anymore.** **`XpReward` is NOT here** — it's enemy-only, on `EnemyControllerBase`/`IEnemy`.
- **Spawner:** Static utility handling entity instantiation and placement. Supports multiple enemy types (Goblins and Archers) and alternates them across BSP rooms.
- **TurnManager:** Pure C# state machine. Enforces sequential game loop (Player Action -> Enemy Action -> Repeat).
- **GameLog:** Pure C# service managing message history. Decoupled from UI via events.
- **Audio (SfxPlayer + SfxBank):** View-side autoload singleton, registered in `project.godot` `[autoload]` as the **scene** `Scenes/SfxPlayer.tscn` (a scene, not the bare script, so its `[Export] SfxBank Bank` can be assigned in the Inspector). `SfxPlayer` (`Code/View/Audio/SfxPlayer.cs`) mirrors the `GameLog.Instance` global-access pattern and holds one `AudioStreamPlayer` per `Sfx` enum value (`Step`/`Hit`/`Death`) so overlapping turn events don't cut each other off; players lazy-build on first use. **Which .wav backs each `Sfx` lives in `SfxBank`** (`Code/View/Audio/SfxBank.cs`), a `[GlobalClass] Resource` authored as `Resources/SfxBank.tres` — a designer swaps/adds sounds in the Inspector without recompiling C# (same pattern as `LevelSettings`). `Play(Sfx)` is null-safe (`Instance?.Play(...)`) and guards `IsInstanceValid`; the typed `Sfx` enum keeps trigger call-sites compile-checked. **Hook points (view-side only — domain stays Godot-free):** footstep in `PlayerController.TryMove` (successful step), `Sfx.Hit` in `ActorController.ReceiveDamage` (any actor taking >0 damage), `Sfx.Death` in the base `ActorController.Die` (enemies only — `PlayerController.Die` overrides without `base` call, so no player-death sound). Assets are dark 8-bit .wavs from the `godot-sound-gen` (jsfxr) skill, regenerable by the seeds documented in `SfxPlayer`.
- **Level Settings:** Godot `Resource` based configuration (`LevelSettings.cs`). Allows tuning spawning parameters (density, difficulty scaling) directly from the Inspector.
- **Combat balance (anti-overrun pass):** player `BaseHealth` 24 (`Player.tscn`), goblin 10 HP / 2 dmg, archer 6 HP / 1 dmg / range 5. `DifficultyScaling` 0.3 (`DefaultLevelSettings.tres` + `LevelSettings.cs` default kept in sync) → `enemyCount = Random(min,max) + base + (floor-1)*0.3` per non-start room. Player render FOV radius is 6 (`Main.UpdateFov`, fog-of-war only). Enemy aggro is now **per-enemy line-of-sight** (sight range 7, see `EnemyAIBase`) — each enemy wakes when *it* has LOS to the player, not when the player's FOV touches it (no aggro broadcast); last-known-position memory then sustains pursuit once LOS breaks.
- **FloorItems:** Pure C# (Godot-free) registry for tracking floor items and managing pickups. Lives in `Code/Domain/Items/`; `GridPos`-native (was `ItemManager`/`Vector2I`).
- **Inventory:** Pure C# component owned by PlayerController. Stores up to 10 items. Emits events for UI updates.
- **Equipment (Loadout + Weapon):** Pure C# (Godot-free, `Code/Domain/Equipment/`). `Weapon` is an immutable VO (`Name`, `DamageBonus`≥1). `Loadout` is the aggregate guarding the equipped weapon: `TryEquip(Weapon)` equips **only if strictly better** (higher `DamageBonus`) and returns whether it did; `Clear()` unequips (on new game); `DamageBonus` exposes the active bonus; `OnEquipmentChanged` notifies the view. The `Player` aggregate owns the `Loadout`; `AttackDamage = base + Loadout.DamageBonus` (the "better?" decision lives in `Loadout`). On the view side, `WeaponItem : ItemController, IEquippable` is a floor weapon that exposes its `Weapon`; `Player.TryPickup` equips it onto the `Loadout` (if better) instead of storing it. `WeaponUI` (`Code/View/UI/`) renders the equipped weapon name from `Loadout.OnEquipmentChanged`.
- **Loot generation:** Pure C# (Godot-free, `Code/Domain/Loot/`). `WeaponLootTable` is a **domain policy/service** (not an aggregate) with its `IRng` injected as a **constructor collaborator**: `Roll(int floorLevel) → Weapon?` (null = no drop). Deeper floors raise the drop chance and the per-step **upgrade chance**: a dropped weapon starts at +1 and is upgraded repeatedly while upgrade rolls succeed, capped at `MaxTier` — so tiers are dynamic (Sword +1, +2, +3, …) and skew higher with depth. Tuning is an immutable `LootTableConfig` VO (drop + upgrade probability knobs + `MaxTier`, self-validating); authored in `LevelSettings` (Inspector) and translated to the VO in `Main.BuildLootConfig` (keeps the domain wall — domain never reads the Godot Resource). `Spawner.SpawnFloorLoot` (view) calls `Roll` and only *places* the returned `Weapon` (random non-start room/tile, walkable-retry). `Main` owns one **run-RNG** (`SystemRng` seeded off `MapSeed`, built in `InitLoot`, reset on restart) shared by the table and placement → a continuous reproducible loot stream across floors. The "what drops" rule lives entirely in `WeaponLootTable`; the view never computes a probability.
- **Randomness seam (`IRng`):** `Code/Domain/Common/IRng.cs` (`NextDouble`, `Next(min,max)`) with `SystemRng` (System.Random-backed, `int? seed`). The domain depends on this abstraction so loot logic is exactly testable via a scripted RNG (`ScriptedRng` test double). Currently used by loot only; `BspDungeonGenerator`/`Spawner` still use concrete `System.Random` (migration is a logged follow-up).
- **ExperienceSystem:** Pure C# logic for XP, leveling, and stat progression. Decoupled from UI via events.
- **Level Generation:** `Main.cs` orchestrates level creation, cleanup, and populating new dungeons when the player uses the stairs. Player state is preserved across levels.
- **Pathfinding:** A* navigation is a query over the grid's own cells, so it lives **on `DungeonGrid`** (`FindPath`, folded in from the deleted `Pathfinder` class, 2.3b). The only public surface is `grid.FindPath(GridPos, GridPos)` (`GridPos`-only since 2.4); the A* work runs in a **hidden per-search `PathSearch` object** so its mutable open/closed state never lives on the long-lived grid. 8-directional: neighbours come from `grid.WalkableNeighbors` (`Direction.AllEight` filtered by `CanStep`), and an octile heuristic (D=10 cardinal, D2=14 diagonal) keeps it admissible. Enemies (`EnemyAI`/`ArcherAI`) call `grid.FindPath` to pursue a visible player and derive their step direction from the path.
- **Game State:** `Main.cs` also manages the game state, handling level transitions and the restart-on-death flow.
- **Advanced Player Actions:**
  - **Shift Move:** Hold Shift + Direction to auto-move until seeing an enemy, hitting a wall, or encountering a corner.
  - **Wait Full Health:** Press Shift + `.` to rest repeatedly until health is fully restored.
    - **Safety:** The action stops automatically if an enemy is spotted, if the player takes damage, or after 200 turns.
  - **Passive Healing:** Player now heals 1 HP every 3 turns automatically.
  - Both actions consume multiple turns and integrate with FOV system for enemy detection.
- **DungeonTileMap & FovTileMap:** Godot `TileMapLayer` nodes. They listen to the purely logical data grids to render specific visual sprites.
- **Minimap:** Godot `Control` node (`MinimapController.cs`) that renders a compact 100×100px grid overview in the bottom-right corner. Data sources: `DungeonGrid` (cell types) and `FovMap` (visibility states). Coloring: Unexplored=hidden, Explored=dark gray, Visible=light gray, walls slightly darker, player=yellow dot. Updated via `Refresh()` which triggers `QueueRedraw()`, called from `Main.UpdateFov()` after each `ComputeFov()`.

## Domain Layer (target architecture)

The codebase is migrating toward a **rich domain model** under full DDD. Target layering (hard physical split):

- `Code/Domain/` — pure C#, **never `using Godot;`** — **enforced by a compile-time wall**: `Code/Domain/` is its own assembly (`RogueLike.Domain.csproj`, plain `Microsoft.NET.Sdk`, **no Godot/GodotSharp reference**), so any `using Godot;` there is a `CS0246` build error, not a grep warning. The Godot game project references it (`EnableDynamicLoading` lets Godot load it at runtime). Value Objects, aggregate roots, world/turn logic, domain events.
- `Code/View/` — Godot nodes only. Render + input, no game rules. The `GridConversions` extension class is the single bridge: `Vector2I`↔`GridPos` plus pixel↔grid (`ToWorldCenter`/`ToGridPos(world, tileSize)`). Extension methods so conversions read off the value (`coord.ToGridPos()`); domain stays Godot-free.

**Domain is organized as vertical slices, not by technical kind.** Each slice owns its types: `Domain/Combat/` (Damage, Health, attack/kill), `Domain/Actors/`, `Domain/Items/`, `Domain/Progression/`, `Domain/World/` (Dungeon — which owns the line-of-sight **and** pathfinding queries over its own cells — and FOV). Pathfinding is **not** a separate type: it folds onto the Dungeon (see "Where spatial logic lives"). `Domain/Common/` is the **thin shared kernel** — ONLY cross-cutting VOs used by many slices (`GridPos`, `Direction`). A type goes in `Common/` only if multiple slices need it; otherwise it lives in its owning slice.

**Value Object catalogue** (immutable `readonly record struct`, invariants in ctor, equality-by-value, no setters):

| VO | Slice | Invariant | Replaces |
|----|-------|-----------|----------|
| `GridPos(X,Y)` ✅ landed (2.2) | Common | none (bounds are the grid's job) | `Vector2I` for positions in the domain |
| `Direction(Dx,Dy)` ✅ landed (2.2) | Common | Dx,Dy ∈ {-1,0,1} | raw `Vector2I` direction deltas |
| `Health(Current,Max)` ✅ landed (2.5) | Combat | Max>0, 0≤Current≤Max | mutable `HealthController` state |
| `GridRect(Position,Width,Height)` ✅ landed (2.6) | Common | Width>0, Height>0; `End` exclusive | `Rect2I` for rooms/BSP partitions |
| `Damage(Amount)` ✅ landed (2.1) | Combat | Amount≥0 | `int AttackDamage` |
| `Weapon(Name,DamageBonus)` ✅ landed (loot) | Equipment | Name non-empty, DamageBonus≥1 | loose weapon name/bonus primitives |
| `Probability(Value)` ✅ landed (loot) | Common | 0≤Value≤1 (implicit→double) | raw `double` chance fields in `LootTableConfig` |
| `XpAmount(Value)` (optional) | Progression | Value≥0 | `int` XP |

`Damage` lives at `Code/Domain/Combat/` (`RogueLike.Code.Domain.Combat`) and is constructed inside `ICombatant.TryAttack`, which calls `defender.ReceiveDamage(damage)` — the combatant applies it to its own `Health` VO (2.5; the old `int` unwrap to `HealthController` is gone).

**Aggregate roots** (pure C#, own state + behavior, raise domain events, no public setters): `Actor` (→ `TryMove`, `Attack`, `TakeDamage`), `Player` / `Enemy` / `Archer` (own their turn/decision behavior), plus `Dungeon`, `ActorRegistry`, `Inventory`, `FloorItems`, `ExperienceTrack`, `TurnEngine`. Godot controllers become Views that observe domain events and render.
